# Zero-Touch Design Rules

모든 UI 화면, 랜딩 페이지, OG 이미지, 광고 소재, 디자인 시스템, UX 카피 설계·검수 시 아래 규칙을 따른다.

1. **스킬 우선 로드**: 디자인·카피·레이아웃 작업이면 즉시 `design-gate`(프로세스·IA·비평)와 `design-system`(토큰·부품·오버라이드) 스킬을 읽고 실행한다.
2. **3단계 오버라이드 우선순위**: **1순위 프로젝트 로컬 파일(`tokens.json`, `tailwind.config.*`, 전용 디자인 문서) > 2순위 현재 세션 사용자 커스터마이징 > 3순위 플러그인 기본 프리셋(Cool Stone & Royal Indigo)**. 기존 프로젝트의 디자인 시스템을 기본 프리셋으로 덮어쓰지 않는다.
3. **Gate 0 선행 (픽셀보다 존재 심사)**: 색·간격 작업 전에 ① 메시지–초점 일치, ② 매체별 정보 예산 준수, ③ 삭제 질문(Cut-First), ④ 타 부서 요청 `What` vs `How` 분리를 먼저 통과한다.
4. **넓게 보고, 작게 자른다 (Think Whole, Ship Thin)**: 맥락·여정·인접 화면은 전체를 보되, 구현은 대표 1조각(1화면 또는 1컷)부터 완성·시각 검증한 뒤 확장한다. 범위 밖 인접 이슈는 이번 패스에 섞지 않고 후속 후보로 분리 기록한다.
5. **계획은 가설 · 실물 백지 비평**: 0~4단계 설계안은 가설이다. 실캡처(`390×844`·`1280×800`)를 볼 때 계획 준수가 아니라 처음 보는 눈으로 "정말 좋은 디자인인가"를 심사하고, 밋밋·공허·어색하면 4단계(구조 대안)로 돌아간다.
6. **불변 품질 하한선**: 어떤 테마에서도 `80-15-5` 면적 법칙, WCAG AA 대비(`4.5:1`/`3.0:1`), `44px` 터치 표적, 화면당 주 버튼 1개, 눈썹·장식 알약·가짜 버튼·`transition-all`·엠대시 금지를 지키고 실캡처 확인 전 완료를 보고하지 않는다.
