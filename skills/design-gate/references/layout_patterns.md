# 정보별 배치·표현 패턴 카탈로그 & 5축 레이아웃 기준표

색·간격·토큰을 고르기 전에 **"이 정보를 어떤 배치·인터랙션 패턴으로 보여줄 것인가"**를 먼저 결정한다. 아래 카탈로그에서 후보 2~3개를 고른 뒤, 5축 기준표로 비교해 채택·탈락 근거를 남긴다.

## 1. 정보 유형별 배치·표현 패턴 카탈로그

| 정보 성격 | 선택 가능한 패턴 | 언제 쓰나 (적합 조건) | 언제 피하나 (금지·주의 조건) |
|---|---|---|---|
| **병렬 비교** | **비교표 · 2~4열 그리드** | 랜딩 가격표·결제 화면처럼 체류 시간이 충분한 곳에서 같은 축의 숫자·조건 2~4개를 1초 만에 비교할 때 | 5열 이상으로 좁아져 단가·헤더가 줄바꿈될 때, 또는 **숏폼 1비트·OG·일반 광고 컷처럼 매체 정보 예산을 초과할 때** |
| **병렬 비교 · 핵심 가치** | **벤토 그리드** | 3~4개 핵심 기능을 1순위(큰 칸) + 보조(작은 칸) 무게 차로 보여줄 때 | 큰 카드 1장이 데스크톱 1뷰포트를 다 먹어 옆·아래 카드와 동시 비교가 깨질 때 |
| **순서 · 시간 흐름** | **세로 타임라인** | 예약→실행→후속처럼 3~5단계 시간 흐름을 한눈에 이해시킬 때 | 순서가 없는 병렬 장점에 `01`/`02` 장식 번호를 붙이는 용도 |
| **순서 · 집중 입력** | **단계형 스텝 · 진행 바** | 한 번에 1개 결정에만 집중시켜 이탈을 줄여야 할 때 | 2~3개 가벼운 입력을 억지로 여러 화면에 쪼개 피로감을 줄 때 |
| **복수 항목 탐색** | **세로 스택 (`RowList`)** | **모바일 기본값.** 모든 항목을 숨김 없이 자연 스크롤·SEO로 노출할 때 | 항목이 8개 이상 길어져 핵심 주 행동을 아래로 밀어낼 때 |

## 2. 5축 레이아웃 의사결정 기준표 (Rubric)

비자명한 화면·섹션·소재를 설계할 때 후보 2~3안은 아래 5축으로 비교해 채택·탈락 근거를 기록한다.

| 평가 축 | 핵심 질문 | 통과 기준 |
|---|---|---|
| **1. 정보 목적 적합성** | 이 배치가 화면의 단 1가지 목표(`One Screen, One Job`)와 1·2·3순위 위계에 맞는가? | 1순위 행동·정보가 첫 시선에 놓이고, 3순위 옵션이 주 동선을 막지 않음 |
| **2. 위아래 인접 요소와의 조화** | 위·아래 섹션·카드와 배경 톤, 시각 밀도, 좌측 정렬 축, 인터랙션 리듬이 자연스럽게 이어지는가? | 인접 덩어리끼리 톤이 녹아 경계가 뭉개지거나, 반대로 무게 낙차·중복 이탈·이중 고정 바 충돌이 없음 |
| **3. 시선 흐름 (`Stop 1 → 2 → 3`)** | 첫 1초 초점(`Stop 1`) → 근거·상태(`Stop 2`) → 주 행동(`Stop 3`)이 끊기지 않고 흐르는가? | 축소 시야(Squint Test)에서 초점이 1곳만 튀고, 폴드 위 잘림이나 하단 30% 이상 공백 쏠림이 없음 |
| **4. 동작 이해 용이성** | 사용자가 별도 설명 없이 "무엇을 누르고 어떻게 움직이는지" 1초 안에 이해하는가? | 누르는 요소와 읽는 요소의 어포던스가 명확하고, 숨은 스와이프·가짜 버튼·예측 못 할 모션이 없음 |
| **5. 매체 · 제약 적합성** | 실제 기기·성능·접근성·채널 제약 안에서 끝까지 유지되는가? | 모바일 `390×844` 한 손 조작·`scrollWidth <= innerWidth`, 데스크톱 `1280×800` 비교성, 정적 HTML·SEO·`prefers-reduced-motion`, 9:16 안전영역 충족 |
