# 매체별 정보 예산표 (Hard Budget) & 요청서 `What/How` 분리

"단순화하라"는 추상 문구 대신, 매체 체류 시간마다 **허용 정보량 상한**을 숫자로 고정한다. 아래 예산을 초과한 요소는 꾸미지 않고 다음 단계(피드 본문·바텀시트·하위 화면·랜딩 페이지)로 이관한다.

## 1. 매체별 Hard Budget

| 매체 (평균 체류 시간) | 1장·1비트당 핵심 초점 | 허용 숫자·데이터 | 다열 비교표 (2~3열) | 상세 정보 이관 위치 |
| :--- | :--- | :--- | :--- | :--- |
| **숏폼·릴스 1비트 (3~4초)** | 1개 | 최대 2개 | **금지** | 랜딩 페이지 (`#price` 등) |
| **정적·캐러셀 1장 (1.5초)** | 1개 | 최대 3개 | **금지** (전용 비교 컷 사전 예외 승인 시만) | 피드 본문 · 랜딩 페이지 |
| **OG·공유 이미지 (1초)** | 1개 | 0~1개 (가격 숫자 금지) | **금지** | 랜딩 페이지 |
| **앱 화면 1장 (5초+)** | 주 행동 1개 | 1~2줄 핵심 요약 | 단순 비교만 허용 | 바텀시트(`Sheet`) · 하위 화면 |
| **랜딩 페이지 (30초+)** | 섹션당 1개 | 제한 없음 | **허용 (`#price`)** | FAQ(`<details>`) · 약관 |

## 2. Gate 0 통과 판정 규칙

1. **메시지–초점 불일치는 즉시 반려**: 제목이 "무료 체험"·"간단한 시작"을 말하는데 시선 1순위(가장 크고 강조된 숫자)가 큰 유료 가격이면 메시지–초점 불일치로 픽셀 작업을 중단한다.
2. **숫자 개수 계산 기준**: 금액, 횟수, 시간, 퍼센트, 기간 등 사용자가 인지해야 하는 독립 수치 조각을 센다(장식 번호 자체는 금지). 상한을 넘기면 반복 수치나 보조 조건을 덜어내고 이관한다.
3. **Cut-First 원칙**: "이 블록을 지우고 랜딩 페이지나 바텀시트로 넘겨도 핵심 목표가 달성되는가?"에 `예`가 나오면 다듬지 않고 제거한다.

## 3. 타 부서·기획 요청서 분리 원칙 (`What` vs `How`)

마케팅·온보딩·운영 등 인접 부서 또는 기획서에서 UI·소재 요청이 들어오면 아래 두 층으로 분리해 접수한다.

- **`What` (반드시 지킬 요구사항)**: 비즈니스 목표, 사용자 행동, 법적·사실 필수 고지, 퍼널·텔레메트리 제약.
- **`How` (참고 배치·UI 형태)**: 요청서에 예시로 적힌 표, 카드 수, 칩 나열, 모달 형태.

디자이너(에이전트)는 `What`을 100% 지키되 **`How`를 고정 스펙으로 받지 않는다.** `How`가 Gate 0 정보 예산이나 `One Screen, One Job`에 어긋나면 0단계에서 삭제·압축·이관 대안을 제시한다.
