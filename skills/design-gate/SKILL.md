# Zero-Touch Design Gate (`design-gate`)

기획서·요청서의 표·카드·칩 구성을 고정 스펙으로 전제하고 픽셀만 다듬는 **"스타일링 함정"**과, 확인 편향 없이 실물로 검증하는 전역 디자인 프로세스 스킬이다. 모든 비자명 설계와 검수는 **Gate 0 → 구조 대안 비교 → 대표 1조각 구현 → 백지 실물 비평** 순서를 강제한다.

## 1. 절대 금지 (Anti-Styling Trap & Cognitive Guardrails)

- **픽셀 선행 금지**: Gate 0을 통과하기 전에 간격(`px`)·폰트·색·테두리·그림자부터 수정하거나 평가하지 않는다.
- **요청서 `How` 고정 금지**: 인접 부서·기획 요청에서 **목표·필수 사실·제약(`What`)**과 **화면 형태·표·배치(`How`)**를 분리한다. `How`는 참고안일 뿐 고정 스펙이 아니다.
- **1안 직행 금지**: 비자명한 화면·섹션·소재는 구조 대안 2~3개 비교 없이 바로 코드를 고치지 않는다.
- **한 패스 일괄 제작 금지 (넓게 보고, 작게 자른다)**: 맥락·여정·인접 화면은 전체를 보되, 구현은 가장 중요한 **대표 1화면(또는 1컷)**에서 먼저 완성·시각 검증한 뒤 파생 비율·화면으로 확장한다. 넓게 보며 발견한 인접 화면·문서 문제는 이번 패스에 섞지 않고 후속 후보로 분리 기록한다.
- **계획 일치 확인 편향 금지 (계획은 가설)**: 0~4단계 설계안은 완성 기준이 아니라 가설이다. 실물 캡처가 계획대로 구현됐더라도 밋밋·공허·어색하면 통과시키지 않고, 처음 보는 눈으로 **"정말 좋은 디자인인가"**를 심사해 가설이 틀렸으면 4단계로 돌아간다.
- **단축 예외**: 단순 오타, 토큰 치환, 1줄 문구 수정만 5~6단계로 단축한다.

## 2. Gate 0 — 존재 심사 · 매체별 정보 예산 (최우선 통과)

설계 착수 또는 검수 보고를 시작할 때 **반드시 아래 3가지 질문에 먼저 답한다**. 하나라도 탈락하면 픽셀 수정·검수를 즉시 멈추고 구조 반려 또는 삭제·이관 대안을 먼저 제시한다. 상세 규칙은 [references/media_budget.md](./references/media_budget.md)를 따른다.

1. **메시지–초점 일치**: 제목(`H1`)이 말하는 핵심 주장과 0.5초 시선 1순위(가장 크고 강조된 요소)가 같은 뜻인가?
2. **매체별 정보 예산 준수**: 아래 표의 숫자 상한과 다열 비교표 금지 규칙을 지켰는가?
3. **삭제 질문 (Cut-First)**: 이 블록을 아예 빼고 다음 단계(피드 본문·바텀시트·하위 화면·랜딩)로 넘겨도 화면의 단 1가지 목표(`One Screen, One Job`)가 더 선명해지는가? (`예`면 꾸미지 말고 뺌)

| 매체 (평균 체류 시간) | 1장·1비트당 핵심 초점 | 허용 숫자·데이터 | 다열 비교표 (2~3열) | 상세 정보 이관 위치 |
| :--- | :--- | :--- | :--- | :--- |
| **숏폼·릴스 1비트 (3~4초)** | 1개 | 최대 2개 | **금지** | 랜딩 페이지 |
| **정적·캐러셀 1장 (1.5초)** | 1개 | 최대 3개 | **금지** (전용 비교 컷 사전 예외 승인 시만) | 피드 본문 · 랜딩 페이지 |
| **OG·공유 이미지 (1초)** | 1개 | 0~1개 (가격 금지) | **금지** | 랜딩 페이지 |
| **앱 화면 1장 (5초+)** | 주 행동 1개 | 1~2줄 핵심 요약 | 단순 비교만 허용 | 바텀시트 · 하위 화면 |
| **랜딩 페이지 (30초+)** | 섹션당 1개 | 제한 없음 | **허용** | FAQ · 약관 · 상세 안내 |

## 3. 모드별 작업 절차 (6-Step SOP)

### 모드 A — 신규 설계 · 화면/소재 개편

1. **Gate 0 심사**: 요청의 `What`(목표·필수 사실·제약)과 `How`(참고 배치)를 분리하고, [references/media_budget.md](./references/media_budget.md)로 뺄 요소·이관할 요소를 먼저 가른다.
2. **1~2단계 (IA · 흐름 · 예외 4종)**:
   - 화면의 단일 목표 1개(`One Screen, One Job`)를 고정하고 정보 목록(Content Inventory)을 **1순위(핵심 행동) · 2순위(보조 정보) · 3순위(접기·시트·랜딩 이관)**로 분류한다.
   - 진입 전 화면과 다음 이동 화면을 먼저 잇고, 정상 상태 외 **빈 상태(empty) · 로딩(loading) · 오류(error) · 긴 텍스트/큰 숫자 넘침(overflow)** 4종을 함께 정의한다.
3. **3~4단계 (레퍼런스 해부 · 구조 대안 2~3안)**:
   - 같은 업종이 아니라 **같은 UX 패턴**의 실제 출시 앱·웹 사례 3~5개(Mobbin 등, 연결 시 활용)를 수집해 "주 행동·안심 문구·닫기·정보 묶음을 왜 그 위치에 뒀는가"만 구조적으로 분해한다.
   - 색·그림자보다 핵심 기능 덩어리부터 잡고, [references/layout_patterns.md](./references/layout_patterns.md) 카탈로그에서 서로 다른 구조 대안 2~3개를 꺼내 **5축 레이아웃 기준표**로 비교해 채택·탈락 근거를 기록한다.
4. **5~6단계 (대표 1조각 구현 · 백지 실물 비평 · 빼기 마감)**:
   - 확정안은 가장 중요한 **대표 1화면(또는 1컷)**부터 실제 카피, 프로젝트 토큰(`design-system` 스킬 기준), [references/principles_14.md](./references/principles_14.md) 14원칙을 적용해 구현한다.
   - 실캡처(모바일 `390×844` · 데스크톱 `1280×800`, 개발 전용 바 숨김)와 **Squint Test**를 볼 때는 계획 준수가 아니라 처음 보는 눈으로 **"정말 좋은 디자인인가"**를 백지 비평한다.
   - 실물이 밋밋·공허·어색하면 **가설 실패**로 판정해 파생 화면으로 확장하지 말고 3~4단계로 돌아간다.
   - 통과 후 마지막 패스에서 중복 라벨·구분선·장식을 빼고 나머지 비율·파생 화면으로 확장한다. 과정 중 찾은 범위 밖 인접 화면·문서 이슈는 후속 후보(또는 티켓)로 분리 기록한다.

### 모드 B — 디자인 검수 · 리뷰 (앱 화면 · 랜딩 · 광고 소재)

1. **Gate 0 먼저 판정**: 픽셀을 보기 전에 대상 매체의 정보 예산 위반, 메시지–초점 불일치, 빼야 할 덩어리를 최상단에 판정한다. Gate 0 탈락 요소는 픽셀 수정안이 아니라 **삭제·압축·이관 대안 2~3개**를 먼저 제시한다.
2. **백지 비평 + 구조·광학·카피 검수**: Gate 0을 통과한 요소에 한해 처음 보는 눈으로 0.5초 초점, 상하 무게 균형(하단 30%+ 공백 쏠림 여부), CRAP 좌측 축, `80-15-5`, [references/principles_14.md](./references/principles_14.md) 금지 UI·타이포 크래프트·카피 톤을 실캡처·픽셀 단위로 검수한다.

## 4. 필수 출력 머리 블록

모든 비자명 설계 제안과 디자인 검수 보고는 **반드시 아래 Gate 0 표로 시작한다**.

```markdown
### Gate 0 심사 (존재 · 정보 예산 · 메시지–초점)
| 대상 | 매체(체류) | 메시지–초점 일치 | 정보 예산 준수 | 삭제·이관 대상 | 판정 |
|---|---|---|---|---|---|
| ... | ... | 통과 / 불일치 | 통과 / 초과(...) | 없음 / ... → 랜딩·시트 | PASS / IA 반려 |
```
